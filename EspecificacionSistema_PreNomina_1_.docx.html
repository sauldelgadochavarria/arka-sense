1. INTRODUCCIÓN Y ALCANCE DEL SISTEMA

Este documento describe en detalle la arquitectura funcional, módulos, catálogos, flujos operativos y requerimientos técnicos del sistema de Pre-Nómina y Control de Tiempo y Asistencia. El sistema está diseñado para automatizar y centralizar la gestión de asistencia, incidencias, turnos y prenómina de empleados en empresas de cualquier tamaño, con integración directa a sistemas de nómina.

1.1 Objetivo General

Desarrollar una plataforma web SaaS multiempresa que permita registrar, controlar y procesar la asistencia del personal mediante dispositivos biométricos, aplicaciones móviles o registros manuales, generando automáticamente la pre-nómina con cálculos de incidencias, horas extra, retardos y justificaciones, para su posterior exportación al sistema de nómina del cliente.

1.2 Alcance Funcional

  • Registro de asistencia por múltiples métodos (biométrico, RFID, facial, móvil, manual)
  • Administración de turnos y horarios flexibles
  • Gestión de incidencias: retardos, faltas, permisos, vacaciones, horas extra
  • Cálculo automático de prenómina por período (semanal, quincenal, mensual)
  • Interfaz bidireccional con sistemas de nómina (Contpaqi, CONTPAQi Nóminas, SAP, ASPEL NOI, etc.)
  • Portal de autoservicio para empleados (consulta de asistencia, solicitudes)
  • App móvil con geolocalización y fichaje para trabajo remoto/campo
  • Panel directivo con KPIs de asistencia y productividad
  • Módulo de seguridad con roles, permisos y auditoría completa

2. ARQUITECTURA DEL SISTEMA

2.1 Arquitectura General

El sistema sigue una arquitectura de microservicios con separación clara de capas. Los módulos críticos (asistencia, biométricos) se desarrollan como servicios independientes para garantizar escalabilidad y disponibilidad.

2.2 Modelo de Multitenancy

El sistema opera en modalidad multi-tenant (una instancia sirve múltiples empresas). Cada empresa (tenant) tiene su propio esquema de base de datos en PostgreSQL, garantizando aislamiento total de datos.

  • Identificación de tenant por subdominio: empresa.sistemanom.mx
  • Schema separation en PostgreSQL por empresa
  • Configuración independiente de reglas de negocio por tenant
  • Facturación y suscripción por empresa

Arquitectura de Base de Datos y Servicios:

  • Modelo Multi-tenant: Aislamiento lógico de datos por cliente mediante un identificador único (tenant_id), garantizando que la información de una empresa sea inaccesible para otras.
  • Microservicios Críticos:
  • Auth Service: Gestión de identidades y sesiones con soporte para biometría móvil (FaceID/TouchID).
  • Payroll Engine: Motor de cálculo asíncrono para pre-nómina, capaz de procesar grandes volúmenes de datos sin degradar la experiencia de usuario.
  • Escalabilidad: Implementación de particionamiento mensual en la tabla de registros de asistencia (attendance_log) para optimizar tiempos de consulta en empresas con más de 1,000 empleados.

3. MÓDULOS DEL SISTEMA

El sistema se compone de 12 módulos principales, cada uno con sus propias funcionalidades, entidades y flujos.

MÓDULO 1: Seguridad y Administración de Accesos

1.1 Descripción

Controla el acceso al sistema, la gestión de usuarios internos (administradores, supervisores, RRHH, operativos) y los permisos granulares por módulo y acción.

1.2 Funcionalidades

  • Gestión de usuarios del sistema (CRUD completo)
  • Roles predefinidos: Super Admin, Admin Empresa, Supervisor, RRHH, Empleado
  • Permisos granulares por módulo: Ver, Crear, Editar, Eliminar, Aprobar, Exportar
  • Autenticación con JWT + refresh token (expiración configurable)
  • Autenticación de dos factores (2FA) por TOTP o SMS
  • Inicio de sesión con biometría en dispositivos móviles (Face ID / Huella)
  • Bitácora de auditoría completa: quién, qué, cuándo, desde dónde
  • Política de contraseñas configurable por empresa
  • Bloqueo de cuenta por intentos fallidos (configurable)
  • Sesiones concurrentes y gestión de dispositivos
  • Recuperación de contraseña por email/SMS
  • Single Sign-On (SSO) via SAML 2.0 / LDAP / Active Directory

  • Sincronización automática con sistema de nómina (ABC)
  • Búsqueda avanzada con múltiples filtros
  • Fotografía y firma digital del empleado
  • QR personal para identificación y checado

MÓDULO 3: Catálogo de Turnos y Horarios

3.1 Descripción

Permite definir y administrar todos los tipos de turno y horario de la empresa. Soporta turnos fijos, rotativos, flexibles y esquemas de trabajo remoto o mixto.

3.2 Tipos de Turno Soportados

  • Turno fijo: Mismo horario todos los días (ej. 8am-6pm L-V)
  • Turno rotativo: Cambia según calendario definido (mañana/tarde/noche por semana)
  • Turno flexible: Entrada libre dentro de un rango, con horas mínimas obligatorias
  • Turno por horas: Personal de medio tiempo o por horas
  • Turno nocturno: Con reglas especiales de cálculo (prima nocturna)
  • Guardia 24x48: Turno especial para vigilancia y seguridad
  • Turno remoto (Home Office): Sin biométrico físico, checado por app/IP
  • Turno mixto: Combinación presencial + remoto

4.4 Procesamiento de Marcaciones

Cada marcación recibida pasa por el siguiente proceso automático:

  1. Recepción de marcación (timestamp, empleado, dispositivo, ubicación)
  2. Validación de empleado activo y turno asignado
  3. Clasificación: Entrada a tiempo, Retardo, Salida anticipada, Hora extra
  4. Cálculo de minutos de retardo o salida anticipada
  5. Actualización del estado diario del empleado
  6. Notificación en tiempo real al supervisor si aplica regla
  7. Almacenamiento en tabla de incidencias automáticas .Especificación Técnica de Seguridad Biométrica:
  • Protocolo de Captura: Los datos biométricos (huellas o rasgos faciales) serán procesados localmente en los dispositivos periféricos.
  • Cifrado de Datos: Solo se transmitirán y almacenarán hashes biométricos unidireccionales. Queda estrictamente prohibido el almacenamiento de imágenes de huellas o rostros en la base de datos central.
  • Algoritmo de Hash: Implementación de cifrado AES-256 para la transmisión de datos entre el hardware y el servicio en la nube (Attendance Engine)

5.3 Flujo de Aprobación de Incidencias

  1. Empleado solicita incidencia desde portal/app → elige tipo, fechas, motivo, adjunta documento
  2. Notificación automática a supervisor directo
  3. Supervisor revisa y Aprueba / Rechaza / Solicita más información
  4. Si requiere segundo nivel → notificación a Gerente o RRHH
  5. RRHH puede aprobar/rechazar definitivo
  6. Empleado recibe notificación del resultado
  7. Si aprobada → se registra en expediente y afecta cálculo de prenómina
  8. Supervisor puede aprobar masivamente un rango de fechas

MÓDULO 6: Gestión de Vacaciones y Ausencias Programadas

6.1 Descripción

Administra el saldo de vacaciones de cada empleado, las solicitudes, el calendario de ausencias del equipo y el cumplimiento de la Ley Federal del Trabajo (LFT) para vacaciones en México.

6.2 Funcionalidades

  • Cálculo automático de días de vacaciones por antigüedad (conforme LFT México)
  • Saldo disponible, tomado y pendiente en tiempo real
  • Solicitud de vacaciones desde portal empleado o app
  • Validación automática de cobertura mínima de personal por área
  • Calendario de equipo para evitar traslapos
  • Bloqueo de períodos críticos (cierre fiscal, temporada alta)
  • Notificación por vencer de vacaciones (aviso 30/60/90 días antes)
  • Prima vacacional: cálculo automático con el período vacacional
  • Reporte de vacaciones pendientes por área para auditoría

Módulo central de cálculo. Consolida todas las marcaciones, incidencias y justificaciones del período para generar la pre-nómina que será exportada al sistema de nómina del cliente.

7.2 Períodos de Cálculo

  • Quincenal (1-15 y 16-fin de mes)
  • Mensual (1 al último día del mes)
  • Decena (cada 10 días)
  • Período especial (configurable por empresa)

7.4 Flujo del Cierre de Período

  1. RRHH abre el período de cálculo (puede ser automático)
  2. Sistema consolida marcaciones del período para todos los empleados
  3. Aplicación de incidencias aprobadas del período
  4. Generación de borrador de pre-nómina
  5. Revisión por supervisores: cada supervisor valida a sus empleados
  6. RRHH revisa incidencias faltantes o inconsistencias
  7. Ajustes manuales autorizados (con bitácora)
  8. Validación final y cierre del período
  9. Exportación al sistema de nómina en formato requerido
  10. Generación de comprobantes de pre-nómina por empleado
  11. Archivado del período para consulta y auditoría

MÓDULO 9: Portal de Autoservicio del Empleado

9.1 Descripción

Interfaz web y móvil para que el empleado consulte su información, registre asistencia (si aplica), haga solicitudes y consulte su historial, sin necesidad de intermediario.

9.2 Funcionalidades

  • Consulta de asistencia del período actual e histórico
  • Visualización del turno y horario asignado
  • Solicitud de incidencias: permisos, vacaciones, justificaciones
  • Consulta de saldo de vacaciones disponible
  • Descarga de comprobante de asistencia del período
  • Notificaciones push: aprobaciones, rechazos, recordatorios
  • Checado de entrada/salida desde app (con GPS y foto)
  • Chat con supervisor para dudas de asistencia
  • Perfil personal: actualización de foto, datos de contacto
  • Historial de solicitudes con estatus

9.3 Checado Móvil con Geolocalización

El empleado puede registrar su asistencia desde la app móvil bajo estas condiciones configurables:

  • Validación de coordenadas GPS dentro de geocerca definida por empresa
  • Foto selfie obligatoria con liveness detection (opcional con IA)
  • Validación de red Wi-Fi corporativa (por SSID o IP)
  • Modo campo: sin restricción de geocerca, pero con registro de coordenadas
  • Historial de ubicaciones de checados para auditoría

5. FLUJOS OPERATIVOS DETALLADOS

5.1 Flujo de Alta de Nuevo Empleado

Este flujo describe el proceso completo desde que se contrata a un empleado hasta que puede registrar asistencia:

  1. RRHH recibe alta desde sistema de nómina (sincronización automática) O crea manualmente
  2. Completar expediente digital: datos personales, contacto, documentos
  3. Asignar empresa, sucursal, departamento, puesto
  4. Asignar turno y horario correspondiente
  5. Cargar foto de perfil y datos bancarios
  6. Enrolar empleado en dispositivo biométrico (huella/facial)
  7. Sistema sincroniza template biométrico al dispositivo asignado
  8. Crear usuario de portal de autoservicio (envío de credenciales por email/SMS)
  9. Empleado ya puede registrar asistencia
  10. Supervisor recibe notificación de nuevo empleado en su equipo

5.2 Flujo de Jornada Laboral Diaria

  1. Empleado llega a la sucursal / ubica su dispositivo biométrico
  2. Coloca huella o rostro en el dispositivo → marcación capturada
  3. Sistema recibe marcación en tiempo real (WebSocket o polling)
  4. Clasifica marcación: Entrada a tiempo / Retardo / Entrada fuera de turno
  5. Si es retardo → calcula minutos y aplica regla configurada
  6. Si hay alerta configurada → notificación al supervisor
  7. Estado del empleado actualizado en dashboard en tiempo real
  8. Empleado sale → misma secuencia con tipo 'Salida'
  9. Sistema calcula horas trabajadas del día
  10. Si faltan marcaciones (p.ej. solo entrada, sin salida) → alerta al siguiente día para RRHH

5.3 Flujo de Solicitud de Permiso (Empleado)

  1. Empleado accede a portal/app → sección 'Mis Solicitudes'
  2. Selecciona tipo de incidencia (permiso con goce, sin goce, etc.)
  3. Indica fechas/horas y motivo de la solicitud
  4. Adjunta documento de soporte si es requerido
  5. Envía solicitud → queda en estatus 'Pendiente'
  6. Supervisor recibe notificación (email + push)
  7. Supervisor revisa en su bandeja de aprobaciones
  8. Aprueba o rechaza con comentario
  9. Sistema notifica al empleado el resultado
  10. Si aprobada → incidencia se registra automáticamente en el período
  11. Si rechazada → no aplica, empleado puede volver a solicitar o apelar

5.4 Flujo de Cierre de Período y Generación de Pre-Nómina

  1. 1-2 días antes del cierre → RRHH recibe recordatorio automático
  2. RRHH revisa listado de incidencias pendientes de aprobación
  3. Supervisores aprueban incidencias pendientes de sus equipos
  4. RRHH verifica empleados con marcaciones incompletas
  5. RRHH aplica ajustes manuales autorizados (con nota y firma electrónica)
  6. RRHH ejecuta el pre-cálculo de prenómina (acción 'Vista Previa')
  7. Sistema genera reporte de pre-nómina borrador con todos los conceptos
  8. RRHH y Nómina revisan el borrador, detectan anomalías
  9. Se realizan correcciones finales
  10. RRHH ejecuta 'Cerrar Período' → sistema bloquea el período para nuevas ediciones
  11. Se genera archivo de exportación en el formato del sistema de nómina
  12. El archivo se sube/envía al sistema de nómina del cliente
  13. Sistema de nómina importa y genera la nómina definitiva
  14. Pre-nómina queda archivada como período cerrado para consulta y auditoría

5.5 Flujo de Integración con Dispositivo Biométrico

  1. Admin registra dispositivo en el sistema (IP, modelo, marca, sucursal)
  2. Sistema establece conexión con el SDK correspondiente
  3. Prueba de conectividad y sincronización de hora
  4. Descarga del catálogo de empleados ya enrolados en el dispositivo
  5. Admin asigna empleados que deben estar en ese dispositivo
  6. Sistema sube los templates biométricos de esos empleados al dispositivo
  7. Dispositivo inicia operación normal → envía marcaciones al sistema
  8. El servicio de polling o push recibe marcaciones y las procesa
  9. Si dispositivo queda offline → sistema alerta y almacena en buffer local
  10. Al reconectarse → descarga marcaciones acumuladas offline

6.3 Seguridad

  • Encriptación en tránsito: TLS 1.3 obligatorio
  • Encriptación en reposo: AES-256 para datos sensibles (CURP, RFC, biométricos)
  • Datos biométricos: No se almacena imagen, solo template cifrado no reversible
  • OWASP Top 10: protección contra SQL injection, XSS, CSRF
  • Sanitización de inputs en frontend y validación en backend
  • Firma de archivos exportados para validar integridad
  • Backups cifrados con retención mínima de 90 días
  • Cumplimiento LFPDPPP (Ley Federal de Protección de Datos Personales) México

6.4 Rendimiento y Escalabilidad

  • Tiempo de respuesta API: < 200ms para el 95% de las peticiones
  • Dashboard en tiempo real con actualización máxima cada 30 segundos
  • Procesamiento de marcaciones: < 5 segundos desde dispositivo a visualización
  • Capacidad: 50,000 empleados por instancia; escala horizontal con K8s
  • Caché Redis para catálogos frecuentes y sesiones
  • Índices optimizados en attendance_records (tabla de mayor volumen)
  • Archivado de marcaciones > 2 años a tabla histórica (cold storage)

6.5 Integraciones Externas

  • SDK ZKTeco: zklib (Node.js) o ZKAccess3 SDK
  • Envío de correo: SendGrid / Amazon SES / SMTP configurable
  • SMS: Twilio / AWS SNS / Nexmo
  • Push Notifications: Firebase Cloud Messaging (FCM)
  • Almacenamiento documentos: AWS S3 o MinIO
  • Firma electrónica: compatible con e.firma SAT México (FIEL)
  • Mapas y geolocalización: Google Maps Platform (Geocoding + Maps JS API)

6.6 App Móvil – Especificaciones

  • Plataformas: iOS 14+ y Android 8+
  • Framework: React Native con Expo (o bare workflow para biométrico nativo)
  • Autenticación biométrica local: Face ID / Touch ID / Android Fingerprint
  • Modo offline: almacena marcaciones y sincroniza al recuperar conexión
  • GPS Background: tracking de ubicación durante jornada (con consentimiento)
  • Notificaciones push: recordatorios, aprobaciones, alertas
  • Cámara: foto selfie obligatoria en checado, con liveness detection opcional
  • Tamaño máximo: < 30 MB descarga inicial
